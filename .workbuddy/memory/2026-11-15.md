## 诊断：登录二维码「刷新」不生效

- 结论：按钮与 `refreshQr → startQrLogin` 链路正常，请求确实发出；但 `/login/qr/key` 的 URL 无唯一参数，被双重缓存，刷新拿回同一个 unikey，生成同一张二维码。
- 根因：`cloud-music-server/server.js:188` `app.use(cache('2 minutes', ...))`；`util/apicache.js:671` 缓存 key = `hostname + originalUrl`（含 query）；响应带 `cache-control: max-age=120`，浏览器 HTTP 缓存同样命中。`/login/qr/check?key=xxx` 也被缓存 2 分钟 → 2 秒轮询始终读到第一次状态，扫码/确认/过期(code 800) 都感知不到。
- 次生风险：手动刷新与过期自动刷新并发 `startQrLogin()`，共享 `qrKey` / `_qrImg`，无请求序号保护，慢响应会覆盖新结果。

## 登录二维码 check 接口 404 修复
- 现象：`/api/login/qr/check?key=...` 报 HTTP 404（body `{code:404,msg:'Not Found'}`），前端 `pollQr`(useLogin.ts:205) 对 404 静默忽略 → 二维码登录卡死无提示。
- 根因：`cloud-music-server/module/login_qr_check.js` 的 catch 块引用未定义 `result.cookie`（try 内 `let result` 在 await 抛错时未赋值），二次抛错冒泡到 `server.js` 顶层 catch，因 `moduleResponse.body` 为空而 `res.status(404).send(...)`。任何让网易云请求异常（key 失效/过期/网络抖动）的情况都表现为 404。
- 修复：catch 改为返回明确业务态 `{status:200, body:{code:800, message:'二维码不存在或已过期'}, cookie:[]}`，不再 404。前端对 800 走「刷新二维码」分支，自愈。

## 修复「歌曲无法完整播放」+「扫码确认后仍登录失败」（已完成，未提交）

- **两问题同源**：上游会话凭证没落地 → 所有接口按游客处理 → `/song/url` 只返回 30 秒试听片段、`/login/status` profile=null。用户感知为「播一半就停」+「扫码确认没登录」。
- **登录失败根因（浏览器 mock 803 + 真实 /login/status 形状复现）**：
  1. `login_status.js` 把 `code`/`profile` 包在 `data` 里，响应是 `{"data":{"code":200,...}}`，顶层无 code；而 `useLogin.onQrLoginSuccess` 判 `status?.code === 200` → 恒 false → 「登录失败，请重试」并重新生成二维码。`user.ts fetchProfile` 同样恒 null。
  2. `loginStatus()` GET 不带唯一 `t`，被 apicache 按完整 URL 缓存 2 分钟 → 扫码成功后仍读到游客态。
  3. 803 的 `body.cookie`（`/login/cellphone`、`/login` 也有）前端完全没保存，只依赖服务端 Set-Cookie（经 Vite 代理 + HttpOnly 不可靠）。没有凭证 → 音源只有试听片段。
- **播放失败根因**：
  1. 并行会话把 `playlist.queryMusicUrl` 从 `/song/url` 改成 `/song/url/v1?level=standard`，实测 10 首里 7 首 v1 返回 `-460 网络环境存在风险` 而旧接口能拿到完整 url；且无 `t`，-460 这个 HTTP 200 被 apicache 缓存 2 分钟，重试一直失败。
