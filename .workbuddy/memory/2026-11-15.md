## 诊断：登录二维码「刷新」不生效

- 结论：按钮与 `refreshQr → startQrLogin` 链路正常，请求确实发出；但 `/login/qr/key` 的 URL 无唯一参数，被双重缓存，刷新拿回同一个 unikey，生成同一张二维码。
- 根因：`cloud-music-server/server.js:188` `app.use(cache('2 minutes', ...))`；`util/apicache.js:671` 缓存 key = `hostname + originalUrl`（含 query）；响应带 `cache-control: max-age=120`，浏览器 HTTP 缓存同样命中。`/login/qr/check?key=xxx` 也被缓存 2 分钟 → 2 秒轮询始终读到第一次状态，扫码/确认/过期(code 800) 都感知不到。
- 次生风险：手动刷新与过期自动刷新并发 `startQrLogin()`，共享 `qrKey` / `_qrImg`，无请求序号保护，慢响应会覆盖新结果。
- 证据：curl 两次 `/login/qr/key` 同 unikey，加 `?t=` 两次均不同；浏览器复现点刷新前后 `imgHash` 均为 `f618c8da945c`、create 的 key 均为 `fd057067-...`；页面内 fetch 同 URL 两次同 key、加 `t` 得新 key。

## 登录二维码 check 接口 404 修复
- 现象：`/api/login/qr/check?key=...` 报 HTTP 404（body `{code:404,msg:'Not Found'}`），前端 `pollQr`(useLogin.ts:205) 对 404 静默忽略 → 二维码登录卡死无提示。
- 根因：`cloud-music-server/module/login_qr_check.js` 的 catch 块引用未定义 `result.cookie`（try 内 `let result` 在 await 抛错时未赋值），二次抛错冒泡到 `server.js` 顶层 catch，因 `moduleResponse.body` 为空而 `res.status(404).send(...)`。任何让网易云请求异常（key 失效/过期/网络抖动）的情况都表现为 404。
- 修复：catch 改为返回明确业务态 `{status:200, body:{code:800, message:'二维码不存在或已过期'}, cookie:[]}`，不再 404。前端对 800 走「刷新二维码」分支，自愈。
- 验证：node 单元验证（mock request reject）确认返回 200/code800，不再抛错。
- 待办：后端进程 PID 14152(19830) 需重启加载新 module；会话无权限结束该进程（拒绝访问），需用户在启动终端 Ctrl+C 或 `taskkill /F /PID 14152` 后 `node app.js` 重启。重启后原 key(已过期~90s前生成) 返回 800，正常流程不再 404。

## 诊断：输入框聚焦出现多余阴影（未改代码，等口径）

- 根因：`src/assets/style/input.css:22` / `:70` 的裸元素规则 `input:read-write:enabled:focus { box-shadow: 0 0 0 2px var(--color-box-focus) }`（`--color-box-focus: rgba(194,12,12,0.18)`），特异性 (0,3,1)，命中所有 input/textarea，包括 Element Plus 内部的 `.el-input__inner` / `.el-textarea__inner`。
- 叠加效应：登录弹窗并行改动 `header-loginform.vue:201` 又给 `.el-input__wrapper.is-focus` 加了 `0 0 0 3px` 外光晕 → 聚焦形成「wrapper 外 3px + wrapper 内 1px 边 + 内部 input 2px 光环」的框中框。`.el-textarea__inner:focus` 原本期望的 EP 1px inset 红边框被全局规则顶掉。
- 实测（Edge + computed style）：cm-input / number / text / el-input__inner / el-textarea__inner 聚焦后均为 2px 淡红光环；`input[type=file]` 因 `:read-write` 不匹配而不受影响；主页 header 搜索框也有该光环。
- 影响面：8 个 el-input、3 个 el-textarea、60+ cm-input（api-console 类页面密集）。
- 方案：A（推荐）两条 focus 规则加 `:not(.el-input__inner):not(.el-textarea__inner)`，2 行；B 全局删 `box-shadow`，2 行但失去 focus ring；C 给 cm-input 加固定 class 并收窄全部选择器，2 文件最彻底。已用注入 CSS 验证 A 可去掉内层竖线、保留外层设计光晕。
- **已按 A 实施**（用户回「a」）：`src/assets/style/input.css` 两条 focus 选择器分别加 `:not(.el-input__inner)` / `:not(.el-textarea__inner)` 并补注释，仅此 1 个文件。浏览器验证 6 类元素全部符合预期：cm-input/text/number/普通 textarea 保留 2px 光环，el-input__inner 无阴影，el-textarea__inner 恢复 EP 的 `1px inset` 红边，file 仍为 none；登录弹窗只剩 wrapper 的 1px inset + 3px 外光晕。`npm run build` EXIT=0，本轮 build 补的 `ElAvatar`/`ElTag` 两行已还原（保留并行会话 staged 的 `ElRadio`/`ElRadioGroup`）。未提交。
