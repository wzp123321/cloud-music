## 播放器「一点就重新播放」诊断（未改代码，待用户确认修复范围）
用 playwright-core + 系统 Edge + 本地 Range-capable WAV 复现（`C:/Users/wanzh/AppData/Local/Temp/cm-audio-debug*.cjs`）：
- 主因（进度条）：`store/player.ts` 的 `@mouseup`→`endDragging()` 先 `play()`，随后 `timeupdate`/`onTimeUpdate` 用旧 `currentTime` 覆盖 `progress`（实测滑块 70 → 5），`@change`→`seek()` 再用被覆盖的值写回 `currentTime`（实测 1.50s，等于旧位置）；不支持 Range 的音源上会跳回 0 重播。
- 次因（点歌）：`startPlayback()` 默认 `el.currentTime = 0`；`cm-table.vue` 的 `linkToDetailPage()` 点歌名也会调 `play()`，导致当前歌曲从头播。
- 附带 bug（首播无声）：队列持久化时 url 置空，刷新后 `startPlayback` 补拉音源触发响应式 `:src` 更新，但 `el.play()` 早于 Vue patch src（实测 `play() called` 时 `src=none`，随后 `ATTR src changed` 且 `paused=true`）。旧版本用 `nextTick(() => startPlayback())` 规避，重构后丢失。
- 已验证正常：暂停→恢复 currentTime 保留（2.18 → 2.24）。
- 建议最小修复：`seek()` 内统一 seek + resume、移除 `endDragging` 的 `play()`；`play()` 命中当前歌曲时不重置；`startPlayback` 内 `await nextTick()` 或显式赋值 `el.src` 后再 `play()`。

## 播放队列 / 切歌诊断（未改代码）
- 现象：歌单里播一首歌后点「下一首」仍是同一首，无法切到歌单下一首。
- 根因 1（主因）：`playlist.addMusic()` 只把被点击的这一首 `unshift` 进队列；歌单详情页没有「播放全部」，专辑/歌手页的「播放全部歌曲」按钮无 `@click` 是空壳。队列长度 1 时 `switchMusic` 的 `(0+1)%1 = 0` 必然回到自己；队列有多首时切到的是历史旧歌，不是歌单下一首。
- 根因 2：底栏「上一首/下一首」绑 `player.onEnded(...)`（走播放模式），单曲循环/随机模式下手动切歌会重播当前曲或落在自己；详情页绑 `switchMusic(...)`，两个入口行为不一致。
- 对标结论：Spotify 官方 FAQ 的 "Next from" —— 播放 artist/album/playlist 中任一曲，该上下文剩余歌曲全部进入队列；只有从 Search 播单曲才生成仅一首的队列。网易云：单曲循环只约束自然结束，手动点下一首仍切歌（QQ 音乐/Vox 才是重播当前曲）。
- `cm-table` 共 4 个使用点（album-detail / artist-detail / playlist-detail / search），均带完整 `dataSource`，在此层做「上下文队列」可一处覆盖全部入口；`PL_PlayVO` 与 `Common_IMusic` 字段一致，可直接复用。
- 建议方案（省力排序）：A 只改底栏按钮改绑 `switchMusic` + `switchMusic` 长度 1 时提示；B 加 `playlist.setQueue(list)` 并在 `cm-table.onPlay` 传整张 `dataSource` 定位当前索引；C 完整上下文队列（含播放来源标记、播放全部按钮接线、手动插队优先队列）。

## 播放修复落地（用户确认「1+2+3 一起改」，仅改 `src/store/player.ts`）
- 修复 3（首播竞态）：`startPlayback()` 在 `el.play()` 前 `await nextTick()`，等 Vue 把响应式 `:src` patch 到 DOM。实测首次点击 `play() called` 时 `src=set` 且出现 `playing`。
- 修复 2（重点当前歌重播）：`play()` 开头判断 `song.id === currentMusic.id` 直接返回（暂停态则 `startPlayback(false)` 恢复），不再 `reset currentTime`、不再重复入队/清歌词。
- 修复 1（进度条回跳，比原诊断多一层）：`endDragging()` 只结束拖拽态，不再 `play()`；`seek(value?: number | number[])` 统一跳转 + 恢复播放，且以 `@change` 的 payload 为权威值（Element Plus `Arrayable<number>` 需兼容数组）；另在 `onTimeUpdate()` 加 `if (!el || el.paused) return` —— 实测 pause 后仍有滞后 timeupdate 把滑块 70 覆盖回 4，仅去掉 endDragging 的 play 不足以修复。
- 关键时序：Element Plus `emitChange = async () => { await nextTick(); emit('change', props.modelValue) }`，故 `@mouseup` 一定早于 `@change`；不能让 mouseup 提前 play 或提前改 progress。
- 验证：`npm run build`（vue-tsc + vite build）通过、`npx eslint src/store/player.ts` 无告警；`C:/Users/wanzh/AppData/Local/Temp/cm-audio-debug5.cjs`（playwright-core + Edge + 本地 Range WAV，通过 `#app.__vue_app__` 的 pinia symbol 拿真实 store）5 项全 PASS：首播无需再点、暂停恢复保留进度、点进度条 70% 跳到 21s 且不回跳、重点当前歌曲不重播、点新歌仍从头播。
